My Development Process

I use a spec-driven workflow where I define requirements before building features and refine them as I develop. This keeps my projects structured, intentional, and aligned with clear goals — resulting in code that is easier to review, test, and extend.

01

Define

Write a mini-spec: user story, acceptance criteria, and scope constraints before any code.

02

Build

Implement the narrowest version that satisfies the spec, committing working increments.

03

Refine

Review against acceptance criteria, update the spec when requirements change, then iterate.
