My Development Process

I use a spec-driven workflow where I define requirements before building features and refine them as I develop. This keeps my projects structured, intentional, and aligned with clear goals — resulting in code that is easier to review, test, and extend.

01

Spec before code

Write acceptance criteria before the first line of code. The spec is the source of truth — not a retrospective summary written after the fact.

02

Ship the smallest version that passes

Implement only what satisfies the current spec. Commit in working increments so the branch is always deployable, not just eventually done.

03

Test against criteria, then update the spec

Verify against acceptance criteria first. If scope changes, update the spec to reflect what actually changed — not what was originally planned.
